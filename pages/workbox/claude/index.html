Workbox 핵심 기능 둘러보기

Workbox는 화면에 무언가를 그리는 라이브러리가 아니라, PWA(오프라인에서도 동작하는 웹앱)를 만들 때 쓰는 서비스워커용 캐싱 도구 모음입니다. 서비스워커는 브라우저와 네트워크 사이에서 요청을 가로채는 백그라운드 스크립트로, Workbox는 이 요청을 "언제 캐시에서, 언제 네트워크에서 응답할지" 정하는 전략을 몇 줄로 쉽게 설정하게 해줍니다.
  • navigator.serviceWorker.register()로 서비스워커를 등록하면 설치 → 활성화 단계를 거침
  • workbox.precaching.precacheAndRoute()로 지정한 파일을 설치 시점에 미리 캐시(프리캐싱)
  • workbox.strategies.StaleWhileRevalidate 등으로 런타임에 요청되는 리소스의 캐싱 전략 지정
  • 한 번 캐시된 리소스는 캐시 스토리지(Cache Storage)에 남아 오프라인 상태에서도 그대로 응답 가능
※ 이 페이지가 등록하는 서비스워커는 pages/workbox/claude/ 경로에만 적용 범위(scope)가 한정되어 있어, 대시보드의 다른 페이지에는 전혀 영향을 주지 않습니다. 아래 위판 시세·공지 내용은 모두 가상의 예시이며 실제 수협중앙회의 자료가 아닙니다. 다른 외부 API는 사용하지 않습니다.

1. 서비스워커 등록 + 생명주기 상태

페이지가 열리면 자동으로 서비스워커를 등록합니다. 등록 상태를 확인해보세요.
확인 중...
코드 보기 
const reg = await navigator.serviceWorker.register('sw.js');
await navigator.serviceWorker.ready;
reg.active.state; // 'activated'
reg.scope;        // 이 서비스워커가 적용되는 경로 범위

2. 프리캐싱 (Precaching)

precache-sample.txt는 서비스워커가 설치되는 시점에 미리 캐시됩니다. 방금 페이지가 로드되자마자 이미 캐시에 들어가 있어야 합니다.
확인 전
코드 보기 (서비스워커 내부) 
workbox.precaching.precacheAndRoute([
  { url: './precache-sample.txt', revision: '1' },
]);
// revision을 바꾸면 파일이 변경됐다고 판단해 다시 캐시함

3. 런타임 캐싱 (StaleWhileRevalidate)

runtime-cached.json은 프리캐시 대상이 아니라, 실제로 요청될 때 캐시됩니다. 버튼을 눌러 요청해보고, 캐시에 저장됐는지 확인하세요.
아직 요청 안 함
코드 보기 (서비스워커 내부) 
workbox.routing.registerRoute(
  ({ url }) => url.pathname.endsWith('/runtime-cached.json'),
  new workbox.strategies.StaleWhileRevalidate({ cacheName: 'workbox-demo-runtime' })
);
// 캐시가 있으면 즉시 응답 + 동시에 백그라운드로 최신 버전을 받아 캐시 갱신

4. 오프라인에서도 동작 확인

1~3번을 먼저 실행해 캐시를 채운 뒤, 브라우저 개발자 도구의 Network 탭 → Offline 체크 → 새로고침으로 실제 오프라인 상태를 만들어보세요. 캐시된 두 파일은 여전히 불러와지지만, 서비스워커가 다루지 않는 not-cached.json은 오프라인에서 실패하는 것을 비교해볼 수 있습니다.
아직 확인 안 함
코드 보기 
// 캐시된 파일은 오프라인에서도 정상 응답됨
await fetch('precache-sample.txt');   // 성공 (프리캐시됨)
await fetch('runtime-cached.json');   // 성공 (런타임 캐시됨, 한 번 요청한 적 있다면)
await fetch('not-cached.json');       // 오프라인이면 실패 (서비스워커가 다루지 않는 파일)
