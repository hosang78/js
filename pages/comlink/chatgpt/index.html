기본 메서드 호출 01

Worker의 함수를 로컬 함수처럼 호출하고 Promise 결과를 받는다.
대기 중
await remote.add(a, b)
await remote.multiply(a, b)

속성 읽기·쓰기 02

원격 객체 속성은 비동기이며, 쓰기는 await로 완료를 기다린다.
대기 중
await remote.profile.name
await (remote.profile.name = value)

비동기 작업 03

Worker 내부 지연 작업과 메인 스레드 UI 반응성을 함께 확인한다.
대기 중
await remote.delayedEcho(text, ms)

콜백 · Comlink.proxy 04

함수는 구조화 복제할 수 없으므로 proxy로 Worker에 전달한다.
대기 중
remote.runWithProgress(Comlink.proxy(cb))

원격 객체 프록시 05

메인 스레드 객체를 복사하지 않고 Worker가 동일 객체의 메서드를 호출한다.
대기 중
await remote.useLogger(Comlink.proxy(logger))

원격 클래스 · new 06

Worker에서 노출한 클래스를 원격 생성하고 인스턴스 메서드를 호출한다.
대기 중
const c = await new remote.Counter(10)
await c.increment(5)

복제 vs Transferable 성능·소유권 07

ArrayBuffer를 기본 구조화 복제로 보낼 때와 소유권을 이전할 때의 시간 및 원본 buffer 분리(detach)를 비교한다.
대기 중
await remote.sumBytes(data)
await remote.sumBytes(Comlink.transfer(data, [data.buffer]))

예외 전파 08

Worker에서 발생한 Error가 호출 측에 다시 throw되는지 확인한다.
대기 중
try { await remote.fail() } catch (error) { ... }

MessageChannel endpoint 09

Worker가 아닌 임의의 postMessage 유사 endpoint에도 expose/wrap을 적용한다.
대기 중
Comlink.expose(api, channel.port1)
Comlink.wrap(channel.port2)

createEndpoint 10

기존 원격 객체에 연결된 새 MessagePort를 만들어 두 번째 proxy를 생성한다.
대기 중
const port = await remote[Comlink.createEndpoint]()
const second = Comlink.wrap(port)

커스텀 transferHandler 11

DOM Event를 필요한 필드만 일반 객체로 직렬화해 Worker로 전달한다.
대기 중
Comlink.transferHandlers.set("EVENT", {...})

windowEndpoint · iframe 12

Window.postMessage 차이를 adapter로 감싸 iframe의 API를 호출한다.
대기 중
Comlink.wrap(Comlink.windowEndpoint(frame.contentWindow))

병렬 호출 13

여러 RPC를 Promise.all로 동시에 요청하고 결과 순서를 확인한다.
대기 중
await Promise.all(tasks.map(remote.fibonacci))

취소 패턴 14

AbortSignal 직접 전송 대신 작업 ID 기반 협력적 취소 패턴을 구현한다.
대기 중

releaseProxy · finalizer 15

proxy 연결을 명시적으로 해제하고 Worker 측 finalizer 호출을 기록한다.
대기 중
remote[Comlink.releaseProxy]()
