3. 특정 요소에만 바인딩

element 옵션으로 문서 전체가 아닌 포커스 영역에서만 반응.

4. keydown · keyup · capture

누름/뗌 이벤트를 구분하고, 캡처와 버블 단계의 실행 순서 확인.

5. 입력 요소 필터

기본값은 INPUT·SELECT·TEXTAREA·contentEditable에서 단축키 차단.

Ctrl+Enter 전송 결과

기본 필터 상태에서는 입력 중 실행되지 않는다.

입력 중 단일 문자 단축키를 허용하면 타이핑과 충돌할 수 있으므로 보통 수정키 조합만 사용.

6. 동적 단축키 빌더

런타임 등록, 같은 스코프 충돌 감지, 개별 unbind를 직접 실습.

single 옵션 지원
아직 동적 등록 없음

7. API 콘솔

등록 목록, 현재 스코프, 눌린 키, 강제 실행, 전체 해제 관련 메서드 확인.

API 버튼을 선택해 결과를 확인해 줘.

8. 지원 키 빠른 참조

수정키 별칭, 특수키, F1~F19, 숫자패드 키 지원. Fn 키는 지원하지 않음.

브라우저 제약

운영체제나 브라우저가 먼저 가져가는 조합은 페이지에서 감지하지 못할 수 있음. 예: 주소창, 탭 닫기, 개발자 도구, 시스템 전환 단축키.

화면 카드 클릭은 trigger() 호출이므로 물리 키 입력과 달리 실제 KeyboardEvent 속성은 비어 있음.
