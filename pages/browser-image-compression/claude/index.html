browser-image-compression 핵심 기능 둘러보기

browser-image-compression도 Compressor.js처럼 캔버스로 이미지를 압축하는 라이브러리지만, "이 용량 이하로 만들어줘" 식의 목표 용량 기반 압축과 웹 워커(멀티스레드) 지원이 특징입니다. Promise 기반 API라 await로 바로 결과를 받습니다.
  • maxSizeMB로 하는 목표 용량까지 자동 압축
  • maxWidthOrHeight로 하는 해상도 제한
  • onProgress로 보는 압축 진행률
  • useWebWorker로 하는 메인 스레드 안 막는 압축
※ 준비된 사진이 없어도 확인할 수 있도록, 그라데이션·도형으로 구성된 가상의 샘플 이미지를 즉석에서 만드는 기능을 함께 제공합니다.
🔒 모든 처리는 브라우저 안에서만 이루어집니다. 업로드한 사진은 서버로 전송되지 않습니다.

이미지 준비

압축 효과를 제대로 보려면 용량이 어느 정도 있는 사진이 좋습니다. 준비된 사진이 없다면 아래 버튼으로 샘플 이미지를 만들어서 확인해 보세요.

1. 목표 용량까지 자동 압축 (maxSizeMB)

quality 값을 직접 정하는 대신, "결과가 이 용량을 넘지 않게 해줘"라고 목표만 주면 라이브러리가 내부적으로 여러 번 시도(기본 최대 10회)해서 맞춰줍니다. 업로드 용량 제한이 있는 서비스에 특히 유용합니다.
소스 코드 보기 
const compressed = await imageCompression(file, {
  maxSizeMB: 0.2,        // 결과가 이 용량을 넘지 않도록 알아서 반복 압축
  useWebWorker: false,
});
console.log(file.size, '→', compressed.size);

2. 해상도 제한 (maxWidthOrHeight)

가로·세로 중 더 긴 쪽이 지정한 값보다 작아지도록 비율을 유지한 채 줄입니다.
소스 코드 보기 
const compressed = await imageCompression(file, {
  maxWidthOrHeight: 300,   // 가로/세로 중 긴 쪽이 300px 이하가 되도록 축소
  useWebWorker: false,
});

3. 압축 진행률 (onProgress)

onProgress는 0~100 사이의 진행률을 여러 번 호출해줍니다. 큰 이미지를 압축할 때 진행 상황을 보여주는 용도로 쓸 수 있습니다.
소스 코드 보기 
await imageCompression(file, {
  maxSizeMB: 0.3,
  onProgress(percent) {
    console.log(percent + '%'); // 0~100 사이 값으로 여러 번 호출됨
  },
});

4. 웹 워커로 압축 (useWebWorker)

useWebWorker: true(기본값)이면 압축 작업이 별도 스레드에서 돌아가서 메인 스레드(화면 반응성)를 막지 않습니다. 워커 안에서 라이브러리 자신을 libURL 옵션의 주소로 다시 불러오기 때문에, 이 주소가 막혀 있으면 워커 압축만 조용히 실패할 수 있습니다.
소스 코드 보기 
await imageCompression(file, {
  maxSizeMB: 0.3,
  useWebWorker: true,
  // 이 라이브러리를 CDN에서 쓴다면, 워커 안에서도 같은 버전을 불러오도록
  // libURL을 명시적으로 고정해두는 게 안전하다 (기본값은 버전 미고정 URL).
  libURL: 'https://cdn.jsdelivr.net/npm/browser-image-compression@2.0.2/dist/browser-image-compression.js',
});
