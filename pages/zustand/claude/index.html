Zustand

Zustand는 아주 작고(약 1KB) 프레임워크에 얽매이지 않는 상태 관리 라이브러리입니다. "하나의 스토어를 여러 곳에서 구독하면 어디서 상태를 바꾸든 구독하는 모든 곳이 자동으로 동기화된다"는 것이 핵심 아이디어입니다. 보통 React 훅과 함께 쓰이지만, 이 페이지는 zustand/vanilla API로 React 없이 순수 JS에서 사용하는 방법을 보여줍니다.

  • createStore()로 상태 + 액션을 한 곳에 정의
  • subscribe()로 상태 변경을 구독 — 여러 UI가 같은 스토어를 보면 항상 동기화됨
  • subscribeWithSelector 미들웨어로 특정 필드만 골라 구독해 불필요한 갱신 방지
  • persist 미들웨어로 상태를 자동으로 localStorage에 저장·복원
⚠️ 이 페이지의 위판·즐겨찾기 데이터는 Zustand 기능 설명을 위한 가상의 예시이며, 실제 수협중앙회의 통계·조직·절차와 무관합니다. 다른 외부 API는 사용하지 않았습니다 (Zustand 5.0.14를 CDN에서 로드).

1. 기본 스토어 — createStore + setState/getState/subscribe

스토어를 만들 때 상태와 액션(상태를 바꾸는 함수)을 같은 객체 안에 정의합니다. 액션 안에서 set()을 호출하면 구독 중인 모든 리스너에게 알림이 갑니다.

현재 입찰가 (store.getState().count)
0
소스 코드 보기 
import { createStore } from 'zustand/vanilla';

const store = createStore((set, get) => ({
  count: 0,
  inc: () => set((s) => ({ count: s.count + 1000 })),
  reset: () => set({ count: 0 }),
}));

store.subscribe((state, prevState) => {
  console.log(`count: ${prevState.count} -> ${state.count}`);
});

store.getState().inc(); // 액션 호출
store.getState().count; // 현재 값 읽기

2. 여러 UI가 하나의 스토어 공유 — 자동 동기화

아래 두 패널은 서로 다른 위치에 있지만 같은 스토어를 구독합니다. 어느 패널에서 항목을 추가하든 두 패널이 동시에 갱신됩니다 — 이것이 Zustand가 "전역 상태 공유"에 쓰이는 이유입니다.

📋 패널 A — 위판 목록에 추가

    📋 패널 B — 같은 스토어를 보는 중

      소스 코드 보기 
      const listStore = createStore((set) => ({
  items: [],
  addItem: (name) => set((s) => ({ items: [...s.items, { id: Date.now(), name }] })),
  clear: () => set({ items: [] }),
}));

// 패널 A, 패널 B 각각 독립적으로 구독하지만 같은 스토어를 봄
listStore.subscribe((s) => renderPanelA(s.items));
listStore.subscribe((s) => renderPanelB(s.items));

      3. 선택적 구독 — subscribeWithSelector

      기본 subscribe는 스토어의 아무 필드나 바뀌면 호출됩니다. subscribeWithSelector 미들웨어를 쓰면 subscribe(selector, listener) 형태로 "이 값이 바뀔 때만" 반응하게 만들 수 있습니다. 아래에서 B값만 여러 번 바꿔도 A 리스너는 반응하지 않는 걸 확인해보세요.

      A 값
      0
      B 값
      0
      "A만 구독"한 리스너 호출 횟수
      0
      소스 코드 보기 
      import { subscribeWithSelector } from 'zustand/middleware';

const store = createStore(subscribeWithSelector((set) => ({
  a: 0, b: 0,
  incA: () => set((s) => ({ a: s.a + 1 })),
  incB: () => set((s) => ({ b: s.b + 1 })),
})));

// a 값만 선택해서 구독 — b가 바뀌어도 이 리스너는 호출되지 않음
store.subscribe(
  (state) => state.a,
  (a, prevA) => console.log('a changed:', prevA, '->', a),
  { fireImmediately: true }
);

      4. persist 미들웨어 — localStorage 자동 저장

      persist()로 스토어를 감싸면 상태가 바뀔 때마다 자동으로 localStorage에 저장되고, 스토어를 새로 만들 때 저장된 값으로 복원됩니다. 즐겨찾기를 토글한 뒤 이 페이지를 새로고침해도 그대로 남아있는지 확인해보세요.

      소스 코드 보기 
      import { persist, createJSONStorage } from 'zustand/middleware';

const store = createStore(persist(
  (set) => ({
    favorites: [],
    toggleFavorite: (name) => set((s) => ({
      favorites: s.favorites.includes(name)
        ? s.favorites.filter((f) => f !== name)
        : [...s.favorites, name],
    })),
  }),
  { name: 'lit-zustand-demo-favorites', storage: createJSONStorage(() => localStorage) }
));
// localStorage['lit-zustand-demo-favorites'] = '{"state":{"favorites":[...]},"version":0}'

      5. 파생 값(Derived State) 계산

      Zustand는 별도의 "computed" 문법이 없습니다. 대신 getState()로 읽은 원본 데이터에서 필요할 때마다 파생 값을 계산하는 함수를 따로 두는 게 일반적인 패턴입니다. 항목을 추가하면 합계가 자동으로 다시 계산됩니다.

      품목중량(kg)kg당 단가금액
      총 위판 금액 (파생 값)
      0원
      소스 코드 보기 
      const store = createStore((set) => ({
  items: [{ name: '고등어', weight: 120, price: 8000 }],
  addItem: (item) => set((s) => ({ items: [...s.items, item] })),
}));

// 파생 값은 필요할 때 직접 계산하는 함수로
function getTotalValue(state) {
  return state.items.reduce((sum, i) => sum + i.weight * i.price, 0);
}

store.subscribe((state) => {
  renderTotal(getTotalValue(state)); // 상태가 바뀔 때마다 다시 계산
});
