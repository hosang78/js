1. 기본 Index 검색

왼쪽 조건을 바꾸면 단일 문자열 Index가 즉시 재생성된다. 검색어 예: 수협, AI, 양식, marine, 보험, workflow

데이터 조작

Index.add / update / remove / contain 기능을 직접 확인한다. 문서 데이터도 함께 갱신된다.

데이터를 추가하거나 수정하면 전체 인덱스를 다시 만든다.

기본 API 코드

const index = new Index({ preset: "default", tokenize: "forward", cache: 100 });
index.add(1, "FlexSearch full-text search");
index.update(1, "FlexSearch fast full-text search");
index.remove(1);
index.contain(1);
const result = index.search("search", { limit: 10, suggest: true });

2. Tokenizer / Preset / Encoder 비교

같은 데이터와 같은 검색어를 여러 설정에 넣어 결과 차이를 비교한다. partial match가 필요한 자동완성은 보통 forward/full 쪽이 유리하고, full은 메모리 사용량이 커질 수 있다.

3. Document Index: 필드·태그·저장소·하이라이트

JSON 문서를 대상으로 title/body/category/author 필드 검색, category/level/tags 태그 검색, enrich/store, merge, pluck, highlight를 확인한다.

Pluck / Store 직접 조회

pluck은 특정 필드를 평평한 결과로 돌려받을 때 편하다. get/set은 내부 store를 확인하거나 수정할 때 사용한다.

store 출력 대기

Document Index 코드

const documentIndex = new Document({
  tokenize: "forward",
  document: {
    id: "id",
    index: [
      { field: "title", tokenize: "forward" },
      { field: "body", tokenize: "forward" },
      { field: "category", tokenize: "strict" },
      { field: "author", tokenize: "forward" }
    ],
    tag: ["category", "level", "tags"],
    store: ["title", "body", "category", "level", "tags", "author", "date"]
  }
});

documentIndex.add({ id: 1, title: "수협 AI 전략", body: "...", category: "AI", level: "실무" });

const result = documentIndex.search({
  query: "수협 AI",
  index: ["title", "body"],
  tag: { category: "AI", level: "실무" },
  enrich: true,
  merge: true,
  highlight: "<mark>$1</mark>"
});

4. Context Search 비교

같은 단어라도 서로 가까이 붙어 있는 문서를 더 높게 볼 수 있는 context scoring 차이를 확인한다.

Context Index는 공식 문서 기준 strict 토크나이저에서만 지원된다.

5. Suggestion 검색

완전 일치하지 않아도 일부 단어가 맞으면 결과를 반환할 수 있다. 예: cat fish, 수협 미확인단어

6. Query Cache

cache 옵션을 켠 Index와 일반 Index를 비교한다. 작은 데이터에서는 차이가 작을 수 있으므로 반복 횟수를 높여 본다.

7. Async Non-blocking

addAsync / searchAsync를 사용해 대량 문서를 비동기 방식으로 넣고 검색한다. UI 블로킹 완화 목적의 기능이다.

8. Resolver: AND / OR / NOT / Boost 스타일 복합 질의

resolve:false로 미해결 결과를 받은 뒤 and/or/not/boost/limit 등을 체인으로 적용한다. 브라우저 번들·버전에 따라 일부 메서드가 제한될 경우 기본 검색 결과를 함께 표시한다.

9. Export / Import / LocalStorage

인메모리 Index를 key/data 단위로 export하고 localStorage에 저장한 뒤, 같은 설정의 새 Index로 import한다.

11. 간이 벤치마크

동일한 synthetic 문서를 여러 토크나이저에 넣어 add/search 시간을 비교한다. 브라우저·기기·데이터 길이에 따라 값이 크게 달라진다.

주의사항 및 한계

  • 이 파일은 FlexSearch를 CDN에서 불러온다. 외부망 차단 환경에서는 flexsearch.bundle.module.min.js를 로컬에 저장한 뒤 import 경로를 수정해야 한다.
  • Worker/Persistent Index는 브라우저 보안 정책, Same-Origin, 별도 설정 파일, DB adapter가 필요할 수 있어 이 샘플에서는 설명과 코드 패턴 중심으로만 다룬다.
  • 한글은 띄어쓰기·조사·복합명사 특성상 영문 자동완성과 다른 검색 품질을 보일 수 있다. 실제 업무 데이터는 형태소 처리나 별도 키워드 필드를 병행하는 편이 안정적이다.
  • FlexSearch는 빠른 클라이언트 검색용으로 좋지만, 권한관리·대용량 색인·동시 업데이트·정교한 랭킹이 필요한 업무 시스템에서는 서버 검색엔진 또는 DB 검색과 함께 설계해야 한다.
