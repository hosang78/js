XState

XState는 앱의 상태를 유한 상태 머신(finite state machine)과 스테이트차트(statechart)로 선언적으로 정의하는 라이브러리입니다. "지금 어떤 상태인가"와 "이 상태에서 어떤 이벤트가 어떤 상태로 바뀌는가"를 명시적으로 그려두기 때문에, 조건문이 뒤엉킨 로직보다 버그를 추적하고 예측하기가 훨씬 쉬워집니다.

  • 계층형(nested) + 병렬(parallel) 상태로 복잡한 시스템을 여러 하위 상태로 쪼개서 표현
  • 가드(guard)로 조건부 전이, after로 시간 기반(지연) 전이
  • invoke로 Promise 등 비동기 작업을 상태 머신 안에 내장 (로딩/성공/실패가 자연스럽게 상태가 됨)
  • 액터(actor) 모델 기반 — 부모-자식 액터를 스폰하고 서로 메시지(이벤트)를 주고받음
⚠️ 이 페이지의 어선·위판·냉동창고·선단 관련 예시는 XState 기능 설명을 위한 가상의 데이터이며, 실제 수협중앙회의 통계·조직·업무 절차와 무관합니다. 다른 외부 라이브러리/API는 사용하지 않았습니다 (XState v5.32.5 UMD 빌드만 CDN에서 로드).

1. 기본 상태 머신 — 어선 조업 상태

createMachine()으로 상태와 전이를 정의하고 createActor()로 실행합니다. context는 머신이 들고 다니는 데이터이고, assign() 액션으로 갱신합니다. 각 상태에는 진입/이탈 시 실행되는 entry/exit 액션을 붙일 수 있습니다.

현재 상태
docked
누적 출항 횟수 (context.trips)
0
소스 코드 보기 
const boatMachine = XState.createMachine({
  id: 'boat',
  initial: 'docked',
  context: { trips: 0 },
  states: {
    docked: {
      entry: () => log('입항 상태 진입'),
      exit: () => log('입항 상태 이탈'),
      on: { DEPART: 'fishing' }
    },
    fishing: {
      entry: XState.assign({ trips: ({ context }) => context.trips + 1 }),
      on: { RETURN: 'docked' }
    }
  }
});
const boatActor = XState.createActor(boatMachine);
boatActor.subscribe((snapshot) => log('상태 변경: ' + snapshot.value));
boatActor.start();
boatActor.send({ type: 'DEPART' });

2. 계층적 + 병렬(parallel) 상태 — 냉동창고 시스템

type: 'parallel'로 정의하면 여러 하위 영역이 동시에 독립적으로 각자의 상태를 가집니다. 냉동창고 예제는 "냉동실 상태"와 "전력 공급" 두 영역이 서로 영향 없이 각각 전이합니다. snapshot.matches({ freezer: 'inspecting', power: 'backup' })처럼 객체 형태로 정확한 조합을 검사할 수 있습니다.

freezer 영역
normal
power 영역
main
소스 코드 보기 
const coldStorageMachine = XState.createMachine({
  id: 'coldStorage',
  type: 'parallel',
  states: {
    freezer: {
      initial: 'normal',
      states: {
        normal: { on: { INSPECT: 'inspecting' } },
        inspecting: { on: { DONE: 'normal', FAIL: 'broken' } },
        broken: { type: 'final' }
      }
    },
    power: {
      initial: 'main',
      states: {
        main: { on: { OUTAGE: 'backup' } },
        backup: { on: { RESTORE: 'main' } }
      }
    }
  }
});
// snapshot.value === { freezer: 'inspecting', power: 'backup' }
// snapshot.matches({ freezer: 'inspecting', power: 'backup' }) === true

3. 가드(guard) + 지연 전이(after) — 품질 신호등

after: { 3000: [...] }는 그 상태에 3초간 머무르면 자동으로 다음 전이를 시도합니다. 배열로 여러 후보를 주면 guard가 true인 첫 번째로 전이합니다. 아래 슬라이더로 재고를 조절하면서, 신호등이 3초마다 재고를 확인해 초록불로 바뀌는지 확인해보세요.

💡 확인된 동작 (v5): 같은 상태로 돌아가는 self-transition(예: red → red)은 XState v5에서 기본적으로 internal transition이라 entry/exit가 재실행되지 않고 after 타이머도 재시작되지 않습니다. 아래처럼 reenter: true를 명시해야 실제로 상태를 다시 진입한 것처럼 타이머가 재가동됩니다. (v4와 달라진 부분이라 마이그레이션 시 특히 주의)
신호등 상태 (3초마다 재확인)
red
현재 재고 (context.stock)
0
재고: 0

가드 조합자 — and() / or() / not()

체크박스로 조건 A/B를 켜고 끄면서, and(['isA','isB']) 와 or(['isA','isB']) 가드로 어떤 전이가 선택되는지 확인합니다.

대기 중
소스 코드 보기 
const signalMachine = XState.createMachine({
  id: 'signal',
  initial: 'red',
  context: { stock: 0 },
  on: { SET_STOCK: { actions: XState.assign({ stock: ({ event }) => event.stock }) } },
  states: {
    red: {
      after: {
        3000: [
          { target: 'green', guard: 'hasStock' },
          { target: 'red', reenter: true } // reenter 없으면 3초 재검사가 멈춤
        ]
      }
    },
    green: { after: { 3000: { target: 'red', reenter: true } } }
  }
}, {
  guards: { hasStock: ({ context }) => context.stock > 0 }
});

// and/or/not 조합자
const guardMachine = XState.createMachine({
  initial: 'start',
  states: {
    start: {
      on: {
        GO_AND: { target: 'passed', guard: XState.and(['isA', 'isB']) },
        GO_OR:  { target: 'passed', guard: XState.or(['isA', 'isB']) }
      }
    },
    passed: {}
  }
});

4. 비동기 액터 (invoke + fromPromise) — 위판 시세 조회 재시도

invoke.src: fromPromise(...)로 Promise를 상태 머신에 내장하면, 로딩/성공/실패가 각각 자연스러운 상태가 됩니다. 이 예제는 매 시도마다 50% 확률로 실패하는 가상 API를 흉내내고, 실패 시 최대 3번까지 guard로 재시도합니다.

현재 상태
idle
시도 횟수
0
조회된 시세
-
소스 코드 보기 
const priceMachine = XState.createMachine({
  id: 'price',
  initial: 'idle',
  context: { attempt: 0, price: null },
  states: {
    idle: { on: { START: 'loading' } },
    loading: {
      entry: XState.assign({ attempt: ({ context }) => context.attempt + 1 }),
      invoke: {
        src: XState.fromPromise(fetchAuctionPrice), // 50% 확률로 reject
        onDone: {
          target: 'success',
          actions: XState.assign({ price: ({ event }) => event.output.price })
        },
        onError: [
          { target: 'loading', reenter: true, guard: ({ context }) => context.attempt < 3 },
          { target: 'failure' }
        ]
      }
    },
    success: { type: 'final' },
    failure: { type: 'final' }
  }
});
// UI에서 완료를 기다릴 때는 waitFor(actor, snap => snap.matches('success') || snap.matches('failure'))

5. 액터 통신 — 선단 관제 (모선 → 자선)

XState의 모든 실행 단위는 "액터"입니다. spawnChild()로 자식 액터를 만들고, 부모는 sendTo(childId, event)로 명령을 보내고, 자식은 sendParent(event)로 보고합니다. 아래는 모선(부모) 액터가 자선 3척(자식)을 스폰해서 각각 출항 명령을 내리는 예제입니다.

소스 코드 보기 
const shipMachine = XState.createMachine({
  id: 'ship',
  initial: 'docked',
  states: {
    docked: { on: { DEPART_ORDER: { target: 'fishing', actions: XState.sendParent(({ self }) => ({ type: 'REPORT', from: self.id, status: 'fishing' })) } } },
    fishing: { on: { RETURN_ORDER: { target: 'docked', actions: XState.sendParent(({ self }) => ({ type: 'REPORT', from: self.id, status: 'docked' })) } } }
  }
});

const fleetMachine = XState.createMachine({
  id: 'fleet',
  entry: [
    XState.spawnChild(shipMachine, { id: 'ship-1' }),
    XState.spawnChild(shipMachine, { id: 'ship-2' }),
    XState.spawnChild(shipMachine, { id: 'ship-3' }),
  ],
  on: {
    COMMAND_DEPART: { actions: XState.sendTo(({ event }) => event.shipId, { type: 'DEPART_ORDER' }) },
    COMMAND_RETURN: { actions: XState.sendTo(({ event }) => event.shipId, { type: 'RETURN_ORDER' }) },
    REPORT: { actions: ({ event }) => log(event.from + ' 보고: ' + event.status) }
  }
});

6. 실시간 상태 인스펙터 — matches() / can()

snapshot.matches(state)로 현재 상태를 확인하고, snapshot.can(event)으로 "지금 이 이벤트를 보내면 실제로 전이가 일어나는지"를 미리 알 수 있습니다. 버튼 활성/비활성을 can() 결과에 그대로 연결해서, 의미 없는 이벤트를 아예 보낼 수 없게 만든 예제입니다. 검수 과정(대기 → 검수중 → 합격/불합격)을 표현했습니다.

현재 상태 (matches)
waiting
시간이벤트결과 상태
소스 코드 보기 
const inspectMachine = XState.createMachine({
  id: 'inspect',
  initial: 'waiting',
  states: {
    waiting: { on: { START: 'checking' } },
    checking: { on: { PASS: 'passed', FAIL: 'failed' } },
    passed: { on: { RESET: 'waiting' } },
    failed: { on: { RESET: 'waiting' } }
  }
});
const actor = XState.createActor(inspectMachine).start();

// 버튼 활성화 여부를 can()으로 결정
startBtn.disabled = !actor.getSnapshot().can({ type: 'START' });
passBtn.disabled = !actor.getSnapshot().can({ type: 'PASS' });

actor.subscribe((snapshot) => {
  console.log(snapshot.matches('checking')); // true / false
});
